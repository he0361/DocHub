# 文档共创工作流

当用户要写一份结构化文档（PRD、设计文档、方案、制度、决策文档等）时，采用三阶段共创流程，通过对话边沟通边推进，而不是一次甩出一大篇：

## 阶段一：收集上下文
- 先问清楚：文档类型、目标读者、要解决的核心问题、必须覆盖的内容。
- 一次问 3~5 个关键问题，避免一次抛太多；信息不足时不臆测，先确认再动笔。

## 阶段二：提炼与结构
- 基于用户给的要点，先给**大纲**（标题层级清晰），请用户确认或调整后再展开。
- 逐节迭代：每节先给草稿，等用户反馈，再按反馈修订定稿。
- 各节风格一致、术语统一；关键数字与结论标注来源。

## 阶段三：读者测试
- 写完后把全文当作"第一次阅读的读者"自检一遍：只凭文档本身能否理解背景、流程与结论？
- 找出依赖对话上下文才能看懂的地方，补全或改写，确保文档可独立交付。

## 原则
- 全程主动引导提问，让用户参与决策，而不是被动接受成品。
- 最终输出 Markdown 格式，便于导出为 .md 或 .docx。
