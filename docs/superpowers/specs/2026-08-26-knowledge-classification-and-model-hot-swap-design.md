# DocHub 知识归类治理、问答提速与模型热更新设计

日期：2026-08-26

## 1. 背景与目标

本次改造解决三个相互关联的问题：

1. 文档画像生成时，知识域与主题完全依赖单次 LLM 判断。LLM 只要生成了不同的 code 或名称，系统就会立即创建新节点。落库前仅有 code/名称完全相等去重，没有候选召回、语义相似度、置信度门禁、并发防重或人工确认，导致同一项目的文档被拆到不同知识域。
2. 开放式问答默认走 ReAct Agent。简单问题在输出正文前仍会执行一次阻塞式 LLM 技能路由，ReAct 又可能调用联网搜索，并携带持续膨胀的 checkpoint 历史。现有日志中普通开放问题从收到请求到首次 Agent 模型请求已有约 3～6 秒，联网问题还会经历“模型决定工具 → 工具请求 → 模型生成答案”的多段等待。当前主要瓶颈不是单一 thinking 开关，但所有支持的模型仍应显式关闭推理模式。
3. ChatModel 与 EmbeddingModel 由 Spring 启动配置一次性构建，运行期无法安全替换。管理员需要在前端配置远程或本地 OpenAI 兼容模型，并让所有用户和后台任务使用新配置；向量模型变更还必须避免新旧向量空间混用。

目标：

- 同项目、同产品或同业务范围的文档优先稳定复用现有知识域与主题。
- 只有“确属全新且高置信度”的结果可以自动创建知识域或主题。
- 低置信度结果不阻塞解析和策略推荐，但必须阻止索引构建，直到用户选择已有节点或确认采用 LLM 建议。
- 普通开放问题不再承担不必要的前置 LLM 与工具调用，显式关闭模型推理模式并限制上下文体积。
- 仅管理员可配置模型；配置经过连接测试后原子热更新，失败不影响当前模型。
- 远程 API 与本地 Ollama、vLLM、LM Studio 等服务统一使用 OpenAI 兼容协议。
- 向量模型更名时采用蓝绿重建，重建成功前始终使用旧模型和旧集合。

## 2. 非目标

- 不引入独立模型网关或外部配置中心。
- 不支持每个普通用户选择不同模型；系统始终只有一套全局生效的聊天配置和一套全局生效的向量配置。
- 不在本次改造中接入非 OpenAI 兼容的本地原生协议。
- 不在前端暴露明文 API Key，也不允许通过查询接口取回完整密钥。

## 3. 总体架构

### 3.1 运行期模型注册中心

新增全局模型配置模块，包含：

- `ModelConfigStore`：读取和保存数据库中的聊天、向量配置及版本历史。
- `ModelCredentialCipher`：使用 AES-GCM 加密 API Key，密钥由服务器环境变量提供。
- `OpenAiCompatibleModelFactory`：根据数据库配置构建候选 ChatModel 或 EmbeddingModel。
- `DynamicChatModel`、`DynamicEmbeddingModel`：作为 Spring `@Primary` Bean 注入现有业务代码，内部通过原子引用委派给当前模型。
- `ModelRuntimeRegistry`：保存当前激活快照、配置版本、模型实例与健康状态。
- `ModelConfigService`：执行管理员校验、候选连接测试、持久化、原子切换与失败回滚。

应用启动时优先加载数据库中的激活配置；数据库尚未初始化时，从 `application.yaml`/环境变量构建启动配置。运行中的请求在开始调用时取得当前快照，已开始的流式请求继续使用旧实例，新请求使用新实例。

配置修改后数据库是事实来源。单实例立即原子切换；多实例通过 Redis 发布配置版本变更，并用定时版本检查兜底，避免部分节点长期使用旧模型。

### 3.2 模型请求地址

管理员配置页直接暴露并保存以下字段，不固定阿里百炼地址：

- 部署类型：远程 API / 本地服务。
- 兼容预设：OpenAI 标准 / DashScope / Ollama 兼容 / 通用兼容。
- Base URL。
- 请求路径：聊天默认 `/v1/chat/completions`，向量默认 `/v1/embeddings`。
- 模型名称。
- API Key；本地服务允许为空。
- 超时、温度、最大输出 Token；聊天配置额外声明是否支持工具调用。

页面展示最终请求地址预览。后端对 URL、协议、内网地址、路径重复和空模型名做校验。服务端允许访问管理员明确填写的本地/内网地址，但连接测试设置严格超时，不把响应正文或密钥写入日志。

## 4. 知识域与主题归类

### 4.1 消除当前副作用

现有 `KnowledgeScopeClassifyService.classify` 在解析 LLM JSON 后立即创建 scope/topic，这是重复节点的直接成因。改造后分类与落库分离：

1. 分类阶段只生成候选与评分，不写知识节点。
2. 独立决策器根据确定性规则、语义评分和 LLM 复核输出 `REUSE`、`CREATE` 或 `REVIEW_REQUIRED`。
3. 只有最终决策为 `REUSE` 或高置信度 `CREATE` 时，事务服务才应用结果。
4. 若上传时已经人工填写知识域，人工输入优先，分类器不得创建其他节点。

### 4.2 多阶段判定

输入不再只截取正文前 1500 字，而是使用文档名、原文件名、章节标题、首部摘要、核心主题和可识别的项目/产品标识构建文档描述。

判定流程：

1. 规范化：统一大小写、全半角、空白、标点和常见编号格式，抽取项目名、产品型号、别名和高区分度词。
2. 确定性候选召回：对 scope/topic 的 code、名称、aliases、description、examples 做精确命中、别名命中、项目标识命中和词法相似度评分。
3. 语义候选召回：使用当前 EmbeddingModel 比较文档描述与节点描述，取得 Top-N 候选。向量服务不可用时退化为确定性候选，不直接新建。
4. LLM 复核：只把 Top-N 候选交给 LLM，要求返回候选 code、是否需要新建、置信度和证据。LLM 不得通过自造 code 假装命中已有节点。
5. 新建二次验证：首次结果建议新建时，再运行一个偏向复用的校验提示；只有两次结果一致、现有候选分数足够低且新颖度足够高时才允许自动创建。
6. 决策门禁：
   - 高置信度复用：综合分达到复用阈值，并与第二候选保持最小分差。
   - 高置信度新建：双重 LLM 结论一致，新颖度达到新建阈值，且没有超过排斥上限的现有候选。
   - 其余情况进入人工确认。

阈值通过 `app.manage.knowledge-classification` 配置，初始建议值由测试样本校准，不把 LLM 自报置信度作为唯一依据。

### 4.3 人工确认与索引门禁

新增知识归类审核记录，保存：文档、版本、状态、LLM 建议、候选列表与分数、理由、最终选择、操作人、操作时间和乐观锁版本。

新增文档知识归类状态：

- `CONFIRMED`：人工指定、自动复用或高置信度自动创建成功。
- `PENDING_REVIEW`：低置信度，等待选择。
- `FAILED`：分类服务异常且无法安全复用。

`PENDING_REVIEW` 不影响内容解析、结构抽取和策略推荐。文档详情页显示醒目的“知识归类待确认”卡片，用户可以：

1. 从已有知识域选择 scope，再从该 scope 下选择 topic；topic 可以选择“无主题”。
2. 查看 LLM 建议的新 scope/topic、理由和置信度，并点击“相信 LLM 建议并创建”。

确认接口在事务中应用知识域、主题、文档元数据与 topic-document relation，并把审核记录置为已处理。索引构建接口在创建任务前强制校验状态；未确认时返回明确的业务错误，不能仅依赖前端禁用按钮。

### 4.4 并发防重与已有重复域处理

scope 增加规范化 canonical key 唯一约束，topic 使用 `scope + canonical key` 唯一约束。自动创建和人工创建共用同一规范化与事务服务；并发冲突时重新读取已有节点并复用，不重复插入。

知识路由管理页增加“合并知识域”能力，用于处理已产生的重复域：管理员选择保留域与待合并域，系统迁移文档元数据、主题和主题文档关系，遇到同义主题时合并关系，随后停用来源域并重建知识路由索引。合并过程保留审计记录且不可静默覆盖。

## 5. 开放式问答提速

### 5.1 已确认的耗时来源

- `SkillSceneRouter` 当前在规则匹配前无条件进行一次同步 LLM 调用，阻塞最终模型请求。
- 所有开放问题默认进入带 Tavily 工具的 ReAct Agent，静态常识问题也可能先联网，再进行第二次模型生成。
- ReAct checkpoint 按 conversationId 长期累计消息，日志中同一会话已增长到 20～29 条模型消息，并重复携带系统时间信息和旧工具结果。
- thinking 仅在 rewrite 阶段显式关闭，主聊天模型没有统一的提供商适配开关。

### 5.2 快速路径

新增 `DIRECT_CHAT` 执行模式：

- 普通开放式问题默认使用 `ObservedChatModelService.streamText` 直接流式回答，不挂载工具。
- 明确包含“最新、今天、搜索、查一下”等时效或联网意图的问题进入 ReAct 工具路径。
- 用户主动选择计划执行时继续使用 `PLAN_AND_EXECUTE`。
- 强制技能仍直接生效；自动技能路由改为规则优先。只有多个高分候选接近且确有歧义时才调用 LLM 复核，无候选时不额外调用模型。

直接回答使用长期摘要加最近窗口，并执行字符/token 预算，不读取无限增长的 Agent checkpoint。ReAct 工具执行使用本轮子线程标识，并把有界历史显式放入问题上下文，避免旧工具轨迹持续累积。

### 5.3 关闭推理模式

所有聊天调用通过统一模型工厂和选项合并器处理：

- DashScope 兼容请求加入 `enable_thinking=false`。
- Ollama 兼容请求加入 `think=false`；若具体服务不接受该扩展参数，连接测试会提示切换兼容预设。
- OpenAI 标准兼容模式不发送服务端不支持的私有字段，并禁止在配置页选择已知的纯推理模式作为低延迟聊天模型。
- rewrite、知识分类、技能路由、推荐问题和文档生成均继承动态模型，但可继续覆盖温度等阶段参数；推理关闭策略不可被阶段参数重新开启。

增加调用阶段、配置版本、输入规模、首次响应耗时、工具耗时和总耗时指标。验收重点是普通开放问题只发生一次聊天模型流式调用，程序内部不再增加同步 LLM 前置等待。

## 6. 管理员模型配置

### 6.1 权限与密钥

模型配置菜单和接口只允许 `is_admin=1` 的账号访问，普通账号即使拥有其他管理权限也不能访问。

API Key 使用 AES-GCM 加密保存。查询接口仅返回 `hasApiKey` 和掩码摘要；编辑时密钥留空表示保留原值。日志、异常、审计 JSON 和前端状态不得包含完整密钥。

聊天模型保存流程：填写 → 测试连接 → 保存并激活。若测试或持久化失败，当前模型保持不变。

向量模型的任何修改都要求：

1. 再次输入当前管理员密码并由后端验证。
2. 准确输入确认短语“我确认更改向量模型”。
3. 候选模型完成 embedding 测试并返回非空、有限数值向量。

### 6.2 聊天模型原子切换

连接测试使用固定短提示，验证同步调用；声明支持工具时额外验证工具调用协议。测试成功后在事务中写入新版本，再替换运行期原子引用并发布版本通知。发布失败时定时版本检查会重试加载。

### 6.3 向量模型凭证更新

当模型名称未变化，仅变更 Base URL、路径或 API Key 时：

- 使用候选配置生成测试向量。
- 校验维度与当前集合一致。
- 管理员完成二次验证后原子切换 EmbeddingModel。
- 失败时继续使用旧配置。

### 6.4 向量模型蓝绿重建

当向量模型名称变化时，不立即激活：

1. 创建待激活配置版本和新的物理 Qdrant collection，collection 名包含配置版本。
2. 使用新 EmbeddingModel 对所有有效文档 chunk 后台重建，记录总数、成功数、失败数和当前文档。
3. 重建期间检索、文档入库和知识分类继续使用旧模型与旧集合。新产生或更新的 chunk 进入迁移增量队列，保证切换前追平。
4. 全量和增量校验成功后，在一个运行期快照中同时切换 EmbeddingModel 与 collection 名，再把新配置标记为激活。
5. 任一步骤失败则保留旧配置和旧集合，页面展示失败原因并允许重试。
6. 旧集合进入可回滚保留期，不在切换事务中立即删除。

同维度但不同模型也必须重建，因为相同维度不代表相同向量空间。

## 7. 前端交互

### 7.1 模型配置页面

管理员侧栏新增“模型配置”，仅真正的管理员可见。页面分为“对话模型”和“向量模型”两个区域，展示当前状态、配置版本、更新人、更新时间和最近测试结果。

页面顶部温馨提示：

> 模型配置会影响所有用户和后台文档任务。请先测试连接再保存。Base URL 必须能从 DocHub 后端所在机器访问；本地模型不能填写仅对浏览器可见的地址。API Key 将加密保存且不会再次完整显示。更换向量模型会触发全量向量重建，重建期间请保持旧模型服务可用。

页面内配置引导：

1. 选择远程 API 或本地服务及兼容预设。
2. 填写 Base URL、请求路径和模型名称，核对最终请求地址预览。
3. 远程服务填写 API Key；本地无鉴权服务可以留空。
4. 点击“测试连接”，通过后保存。
5. 向量配置需在确认弹窗中再次输入管理员密码和指定确认短语。

向量模型更名后页面进入迁移视图，展示集合版本、chunk 进度、失败原因和重试入口。

### 7.2 知识归类确认

文档详情页在概览和策略区之间显示归类卡片。卡片包含当前状态、LLM 建议、候选 Top-N、评分解释和两个明确动作。已有知识域与主题使用级联选择，不允许选择不属于该知识域的主题。

知识路由页显示待确认数量，并提供知识域合并入口。

## 8. 错误处理与回滚

- LLM 分类、embedding 候选召回或二次验证失败时不自动新建节点，进入人工确认或保留人工上传元数据。
- 模型连接测试失败不写激活配置，不替换运行期模型。
- 动态配置加载失败时继续使用上一份有效快照并记录脱敏告警。
- API Key 解密失败视为配置不可用，不回退输出密文。
- 向量迁移失败不切换模型或集合；旧路径持续服务。
- 索引构建同时校验分类状态与当前向量迁移状态，避免竞态条件。
- 所有确认、模型切换、向量迁移和知识域合并写审计记录。

## 9. 数据库变化

新增或调整：

- `dochub_ai_model_config`：模型类型、部署类型、兼容预设、URL、路径、模型名、加密密钥、选项、版本和激活状态。
- `dochub_ai_model_config_audit`：测试、保存、激活、失败和操作人审计。
- `dochub_embedding_migration`：源/目标版本、collection、进度、状态、错误和切换时间。
- `dochub_knowledge_classification_review`：分类候选、建议、状态与最终决策。
- `dochub_knowledge_merge_audit`：知识域合并前后快照。
- `dochub_document` 增加知识归类状态与审核记录引用。
- scope/topic 增加 canonical key 和相应唯一约束。

所有 SQL 同步更新全量建表脚本，并提供可对现有数据库执行的增量迁移脚本。现有记录回填 canonical key；冲突项进入重复候选，不自动破坏性合并。

## 10. 测试与验收

### 10.1 后端自动化测试

- 同项目不同文档名称能够召回并复用同一知识域。
- LLM 建议新建但现有候选较强时进入人工确认，不创建节点。
- 双重验证且高新颖度时只创建一个节点；并发请求仍只有一条记录。
- 低置信度文档完成解析和策略推荐，但索引接口拒绝执行。
- 选择已有域/主题和相信 LLM 两条确认路径均能解除索引门禁。
- 普通开放问题不调用技能 LLM、不挂载搜索工具，只进行一次流式聊天调用。
- 时效/搜索问题仍进入工具路径；历史输入保持在预算内。
- DashScope/Ollama 兼容配置生成关闭 thinking 的请求选项。
- 聊天配置测试失败时当前模型不变，成功时新请求使用新版本。
- 非管理员无法查询、测试或保存配置。
- API Key 加密落库且查询结果不泄漏明文。
- 向量配置缺少密码或确认短语时拒绝。
- 仅换凭证且维度一致时热切换；模型更名时创建蓝绿迁移，失败不切换，成功同时切换模型和 collection。

### 10.2 前端与构建验收

- 管理员看到模型配置菜单，普通账号不可见且直接访问返回无权限。
- 表单校验、URL 预览、密钥保留语义、连接测试状态和温馨提示正确。
- 向量二次确认不能绕过。
- 文档待确认卡片、级联选择和相信 LLM 操作正确。
- Maven 测试与打包通过，前端生产构建通过。

### 10.3 运行验收

- 使用远程 DashScope 配置和本地 `http://127.0.0.1:11434/v1` OpenAI 兼容配置分别完成聊天测试。
- 在长会话中验证普通开放问题不再携带无限增长的 Agent checkpoint。
- 记录改造前后首次正文耗时；普通非工具问题内部链路只含一次模型调用。
- 用两份同项目测试文档验证稳定复用，并用一个真正新领域文档验证高置信度自动创建或人工确认路径。

## 11. 安全与部署说明

- 新增 `DOCHUB_MODEL_CONFIG_ENCRYPTION_KEY`，生产环境必须使用独立高强度密钥并由部署系统注入。
